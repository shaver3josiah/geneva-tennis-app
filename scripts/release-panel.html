1. What GitHub is holding

The builds and the store pushes read these repository secrets. A missing one gets a box below. What you paste goes straight to GitHub and is never shown again, here or anywhere.

2. App Store listing

Sends the description, keywords, age rating, review notes, demo login and newest build from scripts/appstore-metadata.mjs to App Store Connect, then reads every field back. Preview first: it changes nothing and lists what differs.


  


  

    
3. Ship a new version

    
Tags the tip of main. That builds the iPhone app for TestFlight and the Android bundle for Play's internal track. Once Apple has processed the iPhone build, the listing is pushed with that build attached and read back, all by itself, creating the new version in App Store Connect if the last one was already approved. Nothing is sent for review. For an update, write the "What's New" text in App Store Connect before you submit.
